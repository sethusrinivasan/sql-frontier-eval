Business Scenario & Problem

4. Queries Executed (Candidate vs Golden Ground Truth)

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose).
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 297.35 ms) 
WITH ranked_candidates AS
  (SELECT article_id,
          headline,
          vec,
          array_cosine_similarity(vec, [1.0, 0.0]::FLOAT[2]) AS query_sim
   FROM news_articles)
SELECT c.article_id,
       c.headline,
       round(c.query_sim, 4) AS query_relevance,
       round(array_cosine_similarity(c.vec, top1.vec), 4) AS redundancy_with_top1,
       round(0.7 * c.query_sim - 0.3 * array_cosine_similarity(c.vec, top1.vec), 4) AS mmr_score
FROM ranked_candidates c
CROSS JOIN
  (SELECT vec
   FROM ranked_candidates
   ORDER BY query_sim DESC
   LIMIT 1) top1
ORDER BY mmr_score DESC;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 299.08 ms) 
-- First candidate is highest query similarity; score subsequent candidates by query sim minus similarity to article 1
 WITH ranked_candidates AS
  (SELECT article_id,
          headline,
          vec,
          array_cosine_similarity(vec, [1.0, 0.0]::FLOAT[2]) AS query_sim
   FROM news_articles)
SELECT c.article_id,
       c.headline,
       round(c.query_sim, 4) AS query_relevance,
       round(array_cosine_similarity(c.vec, top1.vec), 4) AS redundancy_with_top1, -- MMR formula: 0.7 * Sim(doc, query) - 0.3 * Sim(doc, top1)
 round(0.7 * c.query_sim - 0.3 * array_cosine_similarity(c.vec, top1.vec), 4) AS mmr_score
FROM ranked_candidates c
CROSS JOIN
  (SELECT vec
   FROM ranked_candidates
   ORDER BY query_sim DESC
   LIMIT 1) top1
ORDER BY mmr_score DESC;
