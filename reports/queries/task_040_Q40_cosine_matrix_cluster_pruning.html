Scenario & Frontier Trap
Business Scenario & Problem

Finding all similar document pairs across 100,000 docs is O(N^2) (10 billion checks). Partitioning into coarse category buckets first reduces search to O(N * (N/K)).

4. Queries Executed (Candidate vs Golden Ground Truth) #

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose) and Amazon Aurora Serverless v2 PostgreSQL.
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 1.52 ms) 
SELECT a.doc_id AS doc_a,
       b.doc_id AS doc_b,
       a.bucket_id,
       round(array_cosine_similarity(a.vector, b.vector), 4) AS similarity
FROM corpus a
JOIN corpus b ON a.bucket_id = b.bucket_id
AND a.doc_id < b.doc_id
WHERE array_cosine_similarity(a.vector, b.vector) >= 0.85
ORDER BY similarity DESC;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 1.63 ms) 
-- Pairwise similarity evaluated ONLY within shared bucket partitions

SELECT a.doc_id AS doc_a,
       b.doc_id AS doc_b,
       a.bucket_id,
       round(array_cosine_similarity(a.vector, b.vector), 4) AS similarity
FROM corpus a
JOIN corpus b ON a.bucket_id = b.bucket_id
AND a.doc_id < b.doc_id
WHERE array_cosine_similarity(a.vector, b.vector) >= 0.85
ORDER BY similarity DESC;
