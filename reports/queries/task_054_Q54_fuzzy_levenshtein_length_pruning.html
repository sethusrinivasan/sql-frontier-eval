1. Analytical Significance & What It Means

Scenario & Frontier Trap
Business Scenario & Problem

Users frequently misspell search terms (e.g. 'postgre' -> 'postgresql'). Levenshtein distance counts insertions, deletions, and substitutions.

⚡ The Frontier Trap (Why LLMs Fail)

Computing Levenshtein distance on every catalog word is CPU intensive without pre-filtering on string length (ABS(len_a - len_b) <= max_distance).

Prompt / User Request Given to Model
Users frequently misspell search terms (e.g. 'postgre' -> 'postgresql'). Levenshtein distance counts insertions, deletions, and substitutions.

4. Queries Executed (Candidate vs Golden Ground Truth)

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose).
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 134.56 ms) 
SELECT keyword_id,
       keyword,
       levenshtein(keyword, 'posgresql') AS edit_distance
FROM catalog_keywords
WHERE abs(length(keyword) - length('posgresql')) <= 2
  AND levenshtein(keyword, 'posgresql') <= 2
ORDER BY edit_distance ASC;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 133.79 ms) 
-- Find keywords within edit distance <= 2 of search query 'posgresql'

SELECT keyword_id,
       keyword,
       levenshtein(keyword, 'posgresql') AS edit_distance
FROM catalog_keywords -- Pre-filter: word length cannot differ by more than max allowed edit distance (2)

WHERE abs(length(keyword) - length('posgresql')) <= 2
  AND levenshtein(keyword, 'posgresql') <= 2
ORDER BY edit_distance ASC;
