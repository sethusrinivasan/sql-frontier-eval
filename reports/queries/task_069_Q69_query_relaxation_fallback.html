Scenario & Frontier Trap
Business Scenario & Problem

If a multi-word search query (e.g. 'ergonomic mechanical wireless split keyboard') returns zero results under strict AND matching, modern engines gracefully relax to OR matching.

4. Queries Executed (Candidate vs Golden Ground Truth)

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose).
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 262.53 ms) 
-- Query tokens: 'ergonomic', 'mechanical', 'wireless'
WITH scored_matches AS
  (SELECT id,
          title,
          (CASE
               WHEN title ILIKE '%ergonomic%' THEN 1
               ELSE 0
           END + CASE
                     WHEN title ILIKE '%mechanical%' THEN 1
                     ELSE 0
                 END + CASE
                           WHEN title ILIKE '%wireless%' THEN 1
                           ELSE 0
                       END) AS match_score
   FROM keyboard_catalog)
SELECT id,
       title,
       match_score,
       CASE
           WHEN match_score = 3 THEN 'STRICT_ALL_MATCH'
           ELSE 'RELAXED_PARTIAL_MATCH'
       END AS match_tier
FROM scored_matches
WHERE match_score >= 1
ORDER BY match_score DESC,
         id;
