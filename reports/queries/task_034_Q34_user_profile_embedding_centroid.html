Scenario & Frontier Trap
Business Scenario & Problem

To personalize feeds, recommendation engines compute a dynamic user preference vector by calculating the average centroid of the embeddings of products the user clicked in the last 7 days.

⚡ The Frontier Trap (Why LLMs Fail)

SQL standard lacks native array averaging; unnesting arrays without proper positional indexes scrambles vector dimensions.

4. Queries Executed (Candidate vs Golden Ground Truth) #

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose) and Amazon Aurora Serverless v2 PostgreSQL.
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 1213.17 ms) 
WITH unnested_dims AS
  (SELECT user_id,
          item_id,
          unnest(item_vector) AS val,
          generate_subscripts(item_vector, 1) AS dim_idx
   FROM user_clicks_vectors),
     avg_dims AS
  (SELECT user_id,
          dim_idx,
          round(avg(val), 4) AS avg_dim_val
   FROM unnested_dims
   GROUP BY user_id,
            dim_idx
   ORDER BY user_id,
            dim_idx)
SELECT user_id,
       list(avg_dim_val)::FLOAT[3] AS user_preference_centroid
FROM avg_dims
GROUP BY user_id;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 1235.43 ms) 
-- Calculate element-wise centroid vector for user 42
 WITH unnested_dims AS

          item_id,
          unnest(item_vector) AS val,
          generate_subscripts(item_vector, 1) AS dim_idx
   FROM user_clicks_vectors),
      avg_dims AS
  (SELECT user_id,
          dim_idx,
          round(avg(val), 4) AS avg_dim_val
   FROM unnested_dims
   GROUP BY user_id,
            dim_idx
   ORDER BY user_id,
            dim_idx)
SELECT user_id,
       list(avg_dim_val)::FLOAT[3] AS user_preference_centroid
FROM avg_dims
GROUP BY user_id;
