1. Analytical Significance & What It Means

Scenario & Frontier Trap
Business Scenario & Problem

Demonstrates the classic vector database failure mode where applying relational metadata filters AFTER Top-K vector retrieval discards valid results, returning an empty result set.

⚡ The Frontier Trap (Why LLMs Fail)

Post-filtering vector retrieval (LIMIT 2 inside a subquery before WHERE filters) selects the globally highest similarity items (item 1 and item 2). Because item 1 is $150 (exceeds $50) and item 2 is 'clothing', the outer WHERE filter discards both, returning 0 rows! Relational filters must be applied as PRE-FILTERS.

Prompt / User Request Given to Model
Retrieve the top 2 most semantically relevant products matching query vector [1.0, 0.0]::FLOAT[2] satisfying:
- category = 'electronics'
- price <= 50.00
- in_stock = true

Required output columns:
- item_id (INT)
- price (DECIMAL)
- similarity (DOUBLE)

Order by similarity DESC, item_id ASC. Limit to 2 results.

4. Queries Executed (Candidate vs Golden Ground Truth)

Beautified & Syntax Highlighted
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 12.57 ms) 
SELECT item_id,
       price,
       array_cosine_similarity(vec, [1.0, 0.0]::FLOAT[2])::DOUBLE AS similarity
FROM products_search
WHERE category = 'electronics'
  AND price <= 50.00
  AND in_stock = TRUE
ORDER BY similarity DESC,
         item_id ASC
LIMIT 2;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 13.88 ms) 
SELECT item_id,
       price,
       round(array_cosine_similarity(vec, [1.0, 0.0]::FLOAT[2]), 4) AS similarity
FROM products_search
WHERE category = 'electronics'
  AND price <= 50.00
  AND in_stock = TRUE
ORDER BY similarity DESC,
         item_id ASC
LIMIT 2;
