1. Analytical Significance & What It Means

Scenario & Frontier Trap
Business Scenario & Problem

Fuses BM25 keyword rankings and vector cosine similarity rankings using rank-based Reciprocal Rank Fusion (k=60), preventing unbounded BM25 scores from dominating vector scores.

⚡ The Frontier Trap (Why LLMs Fail)

Frontier models frequently confuse RRF rank fusion with raw score addition (bm25_score + vector_sim). Because BM25 scores can reach 400+ while cosine similarity is bounded between 0 and 1, adding raw scores allows BM25 to completely drown out semantic vector relevance.

Prompt / User Request Given to Model
Combine sparse BM25 lexical scores and dense vector similarity scores using Reciprocal Rank Fusion (RRF):
RRF_Score = 1.0 / (60.0 + bm25_rank) + 1.0 / (60.0 + vector_rank)

Required output columns:
- doc_id (INT)
- title (VARCHAR)
- bm25_rank (BIGINT)
- vector_rank (BIGINT)
- rrf_score (DOUBLE)

Order by rrf_score DESC, doc_id ASC.

4. Queries Executed (Candidate vs Golden Ground Truth)

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose).
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 546.14 ms) 
WITH ranked_bm25 AS
  (SELECT doc_id,
          title,
          row_number() OVER (
                             ORDER BY bm25_raw DESC, doc_id ASC) AS bm25_rank
   FROM search_index),
     ranked_vector AS
  (SELECT doc_id,
          title,
          row_number() OVER (
                             ORDER BY array_cosine_similarity(vec, [1.0, 0.0]::FLOAT[2]) DESC, doc_id ASC) AS vector_rank
   FROM search_index)
SELECT b.doc_id,
       b.title,
       b.bm25_rank,
       v.vector_rank,
       round((1.0 / (60.0 + b.bm25_rank)) + (1.0 / (60.0 + v.vector_rank)), 6) AS rrf_score
FROM ranked_bm25 b
JOIN ranked_vector v ON b.doc_id = v.doc_id
ORDER BY rrf_score DESC,
         b.doc_id ASC;
