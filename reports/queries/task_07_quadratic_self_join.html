1. Analytical Significance & What It Means

Scenario & Frontier Trap
Business Scenario & Problem

Tests whether models leverage native SQL range window frames over non-equi self-joins that cause quadratic memory and CPU explosions.

⚡ The Frontier Trap (Why LLMs Fail)

Frontier models frequently generate triangular self-joins (JOIN ON b.date BETWEEN a.date - 6 AND a.date) instead of standard SQL RANGE window functions. On enterprise data warehouses (Snowflake, BigQuery, DuckDB), this produces an O(N^2) join operator (such as PIECEWISE_MERGE_JOIN or nested-loop joins) that degrades from linear to quadratic complexity and risks memory spills or warehouse timeouts.

Prompt / User Request Given to Model
Calculate the 7-day rolling total revenue for each date in `daily_revenue`.

The 7-day rolling revenue for a given date is the sum of `gross_amount` for that date and the preceding 6 calendar days (e.g., INTERVAL 6 DAYS).

Required output columns:
- revenue_date (DATE)
- gross_amount (DECIMAL)
- rolling_7d_revenue (DECIMAL)

Sort the results by revenue_date ASC.

       gross_amount,
       sum(gross_amount) OVER (
                               ORDER BY revenue_date RANGE BETWEEN INTERVAL 6 days PRECEDING AND CURRENT ROW) AS rolling_7d_revenue
