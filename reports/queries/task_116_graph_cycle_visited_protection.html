1. Analytical Significance & What It Means

Scenario & Frontier Trap
Business Scenario & Problem

Traverses downstream dependencies in a directed acyclic graph that contains an intentional cyclic loop (A -> B -> C -> A), requiring visited path arrays to prevent infinite recursion OOM.

⚡ The Frontier Trap (Why LLMs Fail)

Standard recursive CTEs without cycle tracking (omitting visited array state) enter an infinite recursion loop on cyclic graphs, causing DuckDB or any relational database to fail with a max-recursion limit error or crash with an Out-of-Memory exception.

Prompt / User Request Given to Model
Traverse all reachable downstream tasks starting from 'BUILD_CORE'.
CRITICAL: The graph contains a cyclic dependency ('COMPILE_LIB' -> 'TEST_SUITE' -> 'BUILD_CORE'). The query MUST detect already-visited nodes and terminate traversal to prevent infinite recursion.

Required output columns:
- task_id (VARCHAR)
- min_depth (INT)

Order by min_depth ASC, task_id ASC.

4. Queries Executed (Candidate vs Golden Ground Truth)

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose).
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 1.04 ms) 
WITH RECURSIVE downstream_tasks AS
  (SELECT child_task AS task_id,
          1 AS depth,
          ['build_core', child_task] AS visited_path
   FROM task_edges
   WHERE parent_task = 'BUILD_CORE'
   UNION ALL SELECT e.child_task AS task_id,
                    d.depth + 1 AS depth,
                    list_append(d.visited_path, e.child_task) AS visited_path
   FROM downstream_tasks d
   JOIN task_edges e ON d.task_id = e.parent_task
   WHERE NOT list_contains(d.visited_path, e.child_task))
SELECT task_id,
       min(depth) AS min_depth
FROM downstream_tasks
GROUP BY task_id
ORDER BY min_depth ASC,
         task_id ASC;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 0.86 ms) 
WITH RECURSIVE downstream_graph AS
  (SELECT child_task AS task_id,
          1 AS depth,
          ['build_core', child_task] AS path_nodes
   FROM task_edges
   WHERE parent_task = 'BUILD_CORE'
   UNION ALL SELECT e.child_task,
                    g.depth + 1,
                    list_append(g.path_nodes, e.child_task)
   FROM downstream_graph g
   JOIN task_edges e ON g.task_id = e.parent_task
   WHERE NOT list_contains(g.path_nodes, e.child_task)
     AND g.depth < 10)
SELECT task_id,
       min(depth) AS min_depth
FROM downstream_graph
GROUP BY task_id
ORDER BY min_depth ASC,
         task_id ASC;
