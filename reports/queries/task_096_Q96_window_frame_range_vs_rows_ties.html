1. Analytical Significance & What It Means

Scenario & Frontier Trap
Business Scenario & Problem

In financial auditing, understanding the exact behavioral difference between `ROWS BETWEEN` and `RANGE BETWEEN` prevents duplicate-timestamp errors from failing regulatory ledger reconciliations.

⚡ The Frontier Trap (Why LLMs Fail)

The ANSI SQL default for window frames with ORDER BY is `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, which aggregates identical peers together into one lump sum.

Beautified & Syntax Highlighted

Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 178.26 ms) 
SELECT tx_id,
       val_date,
       amount,
       sum(amount) OVER (
                         ORDER BY val_date RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS bunched_range_total,
       sum(amount) OVER (
                         ORDER BY val_date, tx_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS strict_rows_total
FROM audit_ledger
ORDER BY val_date,
         tx_id;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 164.90 ms) 
-- Compare the difference between default RANGE (peer bunching) vs ROWS (strict sequential)

SELECT tx_id,
       val_date,
       amount, -- Default RANGE behavior: bunches tied dates together ($150 on row 1 and 2)
 sum(amount) OVER (
                   ORDER BY val_date RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS bunched_range_total, -- Explicit ROWS behavior: increments strictly row by row ($100 then $150)
 sum(amount) OVER (
                   ORDER BY val_date, tx_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS strict_rows_total
FROM audit_ledger
ORDER BY val_date,
         tx_id;
