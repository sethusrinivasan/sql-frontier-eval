Scenario & Frontier Trap
Business Scenario & Problem

In build systems (e.g. Webpack, Bazel) or task scheduling, circular dependencies (Task A -> Task B -> Task A) cause deadlocks. The engine must detect cycles and abort gracefully.

4. Queries Executed (Candidate vs Golden Ground Truth) #

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose) and Amazon Aurora Serverless v2 PostgreSQL.
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 1.85 ms) 
WITH RECURSIVE path_finder AS
  (SELECT task_id,
          depends_on,
          [task_id] AS visited_path,
          FALSE AS has_cycle
   FROM task_dependencies
   UNION ALL SELECT p.task_id,
                    d.depends_on,
                    list_append(p.visited_path, d.task_id),
                    list_contains(p.visited_path, d.depends_on) AS has_cycle
   FROM path_finder p
   JOIN task_dependencies d ON p.depends_on = d.task_id
   WHERE NOT p.has_cycle
     AND array_length(p.visited_path) < 10)
SELECT task_id,
       depends_on,
       visited_path,
       has_cycle
FROM path_finder
WHERE has_cycle = TRUE
LIMIT 1;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 1.79 ms) 
-- Detect circular loops using array path tracking
 WITH RECURSIVE path_finder AS
  (SELECT task_id,
          depends_on,
          [task_id] AS visited_path,
          FALSE AS has_cycle
   FROM task_dependencies
   UNION ALL SELECT p.task_id,
                    d.depends_on,
                    list_append(p.visited_path, d.task_id),
                    list_contains(p.visited_path, d.depends_on) AS has_cycle
   FROM path_finder p
   JOIN task_dependencies d ON p.depends_on = d.task_id
   WHERE NOT p.has_cycle
     AND array_length(p.visited_path) < 10)
SELECT task_id,
       depends_on,
       visited_path,
       has_cycle
FROM path_finder
WHERE has_cycle = TRUE
LIMIT 1;
