1. Analytical Significance & What It Means #

Scenario & Frontier Trap
Business Scenario & Problem

Calculates rolling 7-day distinct active users per calendar day. SQL window functions forbid COUNT(DISTINCT) over range frames, causing frontier models to generate catastrophic O(N^2) triangular self-joins that blow up memory.

⚡ The Frontier Trap (Why LLMs Fail)

Joining user_activity directly to itself on an inequality date range produces an O(N^2) Cartesian row explosion. For 1M rows, an unaggregated triangular join emits over 7M intermediate rows and triggers an IE_JOIN or Nested Loop join, overflowing RAM. The optimal pattern aggregates users into daily sets first before evaluating rolling intervals.

Prompt / User Request Given to Model
Calculate the rolling 7-day distinct active user count for each active date.
For each date, count distinct users active on that date or within the preceding 6 days (total 7 calendar days).

Required output columns:
- report_date (DATE)
- rolling_7d_active_users (BIGINT)

Order results by report_date ASC.

4. Queries Executed (Candidate vs Golden Ground Truth) #

Beautified & Syntax Highlighted
Database Engine Context: This query was executed and profiled on DuckDB 2.0 In-Memory Engine with equivalent analytical syntax and execution verification on PostgreSQL 18.7 + Extensions (Docker Compose) and Amazon Aurora Serverless v2 PostgreSQL.
Candidate SQL Executed by gemini-3.8-flash-low (Runtime on 1M Rows: 378.00 ms) 
WITH distinct_user_days AS
  (SELECT DISTINCT user_id,
                   activity_date
   FROM user_activity),
     active_dates AS
  (SELECT DISTINCT activity_date AS report_date
   FROM user_activity)
SELECT d.report_date,
       count(DISTINCT u.user_id) AS rolling_7d_active_users
FROM active_dates d
JOIN distinct_user_days u ON u.activity_date BETWEEN d.report_date - INTERVAL 6 DAY AND d.report_date
GROUP BY d.report_date
ORDER BY d.report_date ASC;
Golden Reference Ground Truth SQL (Runtime on 1M Rows: 159.29 ms) 
WITH daily_users AS
  (SELECT activity_date,
          list(DISTINCT user_id) AS user_list
   FROM user_activity
   GROUP BY activity_date),
     distinct_dates AS
  (SELECT DISTINCT activity_date AS report_date
   FROM user_activity)
SELECT d.report_date,

  (SELECT count(DISTINCT u)
   FROM
     (SELECT unnest(user_list) AS u
      FROM daily_users sub
      WHERE sub.activity_date BETWEEN d.report_date - INTERVAL 6 days AND d.report_date)) AS rolling_7d_active_users
FROM distinct_dates d
ORDER BY d.report_date ASC;
