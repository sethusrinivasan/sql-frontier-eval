## ⏱️ Video Timeline & Teleprompter Script

### [0:00 - 0:45] PART 1: The Problem & Motivation (Why Analytical SQL Evals Matter)
**Visual on Screen:** Title Slide from `walkthrough_presentation.html` -> Split screen with Spider benchmark vs Production Warehouse.

> **Speaker Script:**  
> *"Hi everyone, welcome to SQL-Frontier-Eval.  
> 
> Most text-to-SQL benchmarks today—like Spider or BIRD—focus on simple textbook queries. They test whether a model knows how to write a basic `SELECT ... WHERE` or join two tables.  
> 
> But in enterprise analytics—on Snowflake, BigQuery, Databricks, or DuckDB—the failure modes from frontier AI are far more subtle and dangerous.  
> 
> The biggest danger isn't a SQL syntax error. If an LLM writes invalid syntax, the database fails fast and rejects the query. The real disaster is **silent metric corruption**—queries that execute with code 0, but silently inflate financial KPIs by 400%, or drop active customers due to three-valued NULL logic.  
> 
> We built **SQL-Frontier-Eval** to benchmark and protect against these real-world analytical failure modes."*

---

### [0:45 - 1:45] PART 2: The 8-Category Analytical Failure Taxonomy
**Visual on Screen:** Slide showing the 8 taxonomy cards with highlighted diagrams.

> **Speaker Script:**  
> *"Our evaluation suite tests frontier models across 8 distinct failure modes that trip up LLMs in real-world data warehouses:
> 
> 1. **The Chasm Trap**: Multi-table 1-to-N joins before grouping, creating Cartesian fan-outs that multiply sales numbers.
> 2. **Gaps & Islands Sessionization**: Complex clickstream timeouts requiring cumulative step flags rather than naive row numbers.
> 3. **SCD Type 2 Point-in-Time Joins**: Historical currency conversion with open-ended NULL upper bounds.
> 4. **Three-Valued Logic in Anti-Joins**: Where `NOT IN` with a single NULL returns empty sets.
> 5. **Window Frame Default Bounds**: The silent pitfall of default `RANGE` frames bundling duplicate timestamps together.
> 6. **Strict Funnel Precedence**: Ensuring multi-step user onboarding conversions obey chronological event ordering.
> 7. **Quadratic Self-Joins**: Trapping models that write $O(N^2)$ triangular self-joins instead of linear window scans.
> 8. **Non-SARGable Partition Pruning**: Preventing date function wraps that crash large warehouse scans.
> 
> Every single task includes isolated DuckDB DDL fixtures, deterministic multiset verification, floating-point tolerance, and execution plan profiling."*
